# Setup interview

When the user asks to set up (or the data folder has no `search.json`), run this interview, then generate their files.

**How to talk.** Ask **one question at a time**, at most ten, and wait. Write each question **once**: do not repeat it after a tool call, and do not restate earlier answers. Acknowledge the previous answer in five words or fewer ("Got it: senior product roles."). Plain language, no jargon. Offer a sensible default where one exists. British English unless the user writes otherwise. Before the first question, check for an existing data folder with a command that cannot fail (for example `ls data 2>/dev/null; true`), so the user never sees a red error. Do the same for every optional check: end it with `; true`, and use `data/<file>` paths, never the repo root.

**Format.** Start every question with its number and label in bold, exactly as listed below: "**Question 3 of 10: Sectors.**" followed by the question text; the follow-up is "**Question 3b of 10: Exclusions.**". Ask each question with exactly the text given, with one exception: in question 2 you may add up to three example titles taken from the user's own answer to question 1, never from any other field. Never skip the number, never merge two questions, never offer preset answer buttons for a question that expects the user's own words (a yes or no confirmation may have buttons). Never invent answers. Anything the user skips stays `null` or empty and is flagged in plain words as "(check this)".

## Questions
1. **Role and level.** Ask: "Which job titles do you want, and at what level (senior, lead, head of)?" Keep any examples generic; never assume their field.
2. **Titles to skip.** Ask: "Which look-alike titles should I ignore? Say 'none' to skip."
3. **Sectors.** Ask: "Which sectors or kinds of company are you after (for example SaaS, fintech, climate, developer tools), and what size or stage (startup, scale-up, enterprise)?"
3b. **Exclusions.** Ask as its own short message after they answer 3, never combined with it: "Is there any sector or company you won't work for? For example 'no gambling or defence', or company names. Say 'none' to skip." This is part of question 3, so the interview still has ten questions.
4. **Location and work mode.** Ask: "Which places can you work from (cities or countries), and do you want remote, hybrid or office roles?"
5. **Office days.** Ask: "What is the most office days a week you would accept? Use 0 for fully remote."
6. **Pay.** Ask: "What are your pay floor and target, with currency and whether it is per year or per day? How should ads with no listed pay be treated: reported anyway (flagged as unlisted) or dropped?"
7. **Report channel.** Ask: "Should the report be saved as a file only, or also emailed to you? If emailed, which one address? It is the only address the tool will ever write to, and it needs an email connector set up in Claude."
8. **How often.** Ask: "How often should careers-page-watch run? Every weekday (the default), once a week (which day), or another rhythm?" It never runs more than once a day; if they ask for more, say so kindly and offer daily.
9. **Anything else.** Ask: "Is there anything else that rules a job in or out? For example: you need visa sponsorship, you can't relocate, or you won't travel more than 10%. Say 'nothing' to skip." The answer goes into the hard filters, so the agent can skip those ads.
10. **Employers to watch.** Read `templates/companies.starter.csv` and ask: "The starter list has these employers: <the names from that file>. Which employers do you want watched? (a) the starter list only, (b) the starter list plus your own, or (c) only your own. You can add or remove employers at any time, so there is no pressure to name many now." If they choose (b) or (c), follow up with: "Which employers do you want watched? Name as many as you like and I'll look up their job boards." Never assume the starter list is included unless they choose (a) or (b).

## Then do this
1. `python3 init_data.py` to create the data folder (or `$CPW_DATA`).
2. Write `search.json` from the answers: `title_regex` (alternation of title keywords, lower-case), `title_exclude_regex`, `eligible_places`, `place_synonyms` (wider phrases that include their places: for every city they named, put its country in `eligible_places` too, and for a US city its state; in `place_synonyms` use the phrases for their region, for example EU, EMEA and Europe for a European place; United States, US, USA, North America and Americas for a US place; and worldwide, anywhere and global for any place), `max_office_days`, `pay_floor`, `pay_currency`, `report_email_to`, `email_when_quiet` (true unless they asked for no quiet-day notes). Show it and check the regexes against two titles they would want and two they would not.
3. Write `criteria.md` from the answers (answer 9 goes under "Hard filters"). Mention only what they told you.
4. Build `companies.csv` from their choice in question 10: the starter rows for (a) and (b), their own employers for (b) and (c); for (c) remove the starter rows. For each added employer find its board with `python3 find_board.py` as in `AGENT.md` step 9 (a, b); if the user gave a careers page or job link, pass that exact address. Employers on other systems get `ats=browser` with their careers page address in the `slug` column (so the report can link to it), or `skip`; say which ones.
5. First run. Do **not** use `./run.sh` here: it saves its own report and marks every ad as seen, so your first Claude run would find nothing new. Instead run `python3 -W ignore scan.py` and then `python3 -W ignore report.py --dry-run` (prints the standalone verdicts and changes nothing). Then follow `AGENT.md` to judge the ads, write the first report and fill `seen.json`. Email it if an address was given.
6. **Offer the schedule.** Use their answer to question 8. First ask for the time, as an open question: "At what time of day should it run? For example 08:00 or 09:30; the app adds a short delay." The user types the time: do not offer suggested times as buttons or quick replies, and never present a time as already decided; accept any time they type. Then say in plain words what you will set up and ask for a clear yes: a run at that time on their days (a weekly rhythm is one run a week on their day), a backup run about two hours later that only does anything if the first run was missed (laptop asleep or the app closed), and a one-line note on quiet days so they know it ran. They can say "no backup" or "no notes" to switch either off. If a scheduled-task tool is available, create the tasks only after the yes, using the prompts in [docs/scheduling.md](docs/scheduling.md). Otherwise point to that file.
7. **Closing message (always).** End with a short, plain "Setup complete" message that says:
   - what was created: the settings in the data folder, and where today's first report is, as a full path from this folder (for example `data/reports/report-DATE.md`) so the link opens (and that it was emailed, if it was);
   - employers watched: exactly the names in `companies.csv`, saying which are scanned and which are `browser` or `skip` (to check by hand). Never name an employer the user did not choose;
   - what happens next: whether a run is scheduled, how often and when, and whether a backup run and quiet-day note are on; or that nothing runs by itself yet and how to run it ("open this folder and say: run today's report");
   - what it needs: the Claude app open on this computer at the scheduled time; an email connector if emailing;
   - how to change things later: say "change my settings", or edit `data/search.json`; employers can be added or removed at any time;
   - tell me when you apply: say "I applied to <company>, <role>, on <date>" at any time, and I will note it in `data/applied.csv` so the tool stops listing that role as new and tells you if it changes or closes;
   - how to stop or remove it: [docs/uninstall.md](docs/uninstall.md);
   - that the agent only reports and never applies or contacts anyone.
   Use plain names for the scheduled tasks as the user sees them under Scheduled (for example "Job ad report" and "Job ad report backup"); never mention internal task names or ids, not even to explain a name clash (if a name is taken, silently choose another).
